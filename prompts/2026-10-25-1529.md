RED is done: I added 17 parametrised validation cases for adding a vehicle. 10 of them fail for the expected reason (the API returns 201 where the test expects 422). The other 7 already pass because the current schema rejects those inputs.

The new test is `test_adding_vehicle_with_invalid_payload_returns_422` in `backend/tests/test_vehicles.py`. It logs in as an admin and posts each bad payload. The cases are built from the existing `VEHICLE` payload:
- **Missing field:** one case per field (make, model, category, price, quantity).
- **Blank or whitespace:** `""` and `"   "` for each of make, model and category.
- **Price:** `"0"`, `"-1.00"` and `"24999.999"`.
- **Quantity:** `-1`, `1.5` and `"abc"`.

**Failing (10):** all six blank/whitespace cases, zero price, negative price, price with 3 decimals, and negative quantity. Each one fails with `assert 201 == 422`, not an import or syntax error.

**Already passing (7):** the five missing-field cases, quantity `1.5` and quantity `"abc"`. Pydantic already treats all fields as required and refuses those two values for an `int`. This breaks the one-behaviour-per-cycle rule a little, since those 7 cases need no production code. They are still useful as regression guards.

No production code was changed and nothing is committed.
