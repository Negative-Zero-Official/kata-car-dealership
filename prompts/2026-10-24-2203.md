**What the test checks:**
1. It registers `alice@example.com`, then logs in with `POST /api/auth/login` and expects a 200.
2. The response has `token_type == "bearer"`, and `user` is exactly `{id, email, role}`, matching the registered user.
3. The token decodes with `settings.JWT_SECRET`, and its claims include:
   - `sub == str(user_id)`
   - `role == "user"`
   - `exp` within 60 seconds of now plus `JWT_EXPIRE_MINUTES`

**Assumptions built into the test:**
- **The token is signed with HS256.** The test fails if GREEN signs it with a different algorithm.
- **`sub` is a string.** PyJWT's decode rejects a token whose `sub` isn't a string, so the user id has to be stored as one.
- **The login body is JSON `{email, password}`,** the same shape as register, not the OAuth2 form-encoded format.

I didn't touch any production code.

```python
def test_login_returns_bearer_token_with_user_claims(
    client: TestClient, settings: Settings
) -> None:
    registered = client.post(
        "/api/auth/register",
        json={"email": "alice@example.com", "password": "s3cret-password"},
    ).json()

    response = client.post(
        "/api/auth/login",
        json={"email": "alice@example.com", "password": "s3cret-password"},
    )

    assert response.status_code == 200
    body = response.json()
    assert body["token_type"] == "bearer"
    assert body["user"] == {
        "id": registered["id"],
        "email": "alice@example.com",
        "role": "user",
    }

    claims = jwt.decode(body["access_token"], settings.JWT_SECRET, algorithms=["HS256"])
    assert claims["sub"] == str(registered["id"])
    assert claims["role"] == "user"
    expected_exp = time.time() + settings.JWT_EXPIRE_MINUTES * 60
    assert abs(claims["exp"] - expected_exp) < 60
```
