**What changed:**
- **`app/services/token.py`** (new): `TokenService(secret, expire_minutes).issue(user)` signs an HS256 token containing `sub` (the user id as a string), `role` and `exp` (now plus the configured expiry).
- **`app/services/auth.py`**: `AuthService` now takes a `TokenService`. The new `login(email, password)` method returns `(token, user)`.
- **`app/dependencies.py`**:
  - `get_settings` reads `app.state.settings`, so tests get the test secret.
  - `get_token_service` builds the `TokenService` from those settings.
  - `get_auth_service` passes it into `AuthService`.
- **`app/schemas/auth.py`**: two new schemas:
  - `LoginRequest {email, password}`
  - `TokenResponse {access_token, token_type="bearer", user}`
- **`app/routes/auth.py`**: a thin `POST /login` that calls the service and maps the result to the response.

**What's deliberately left out**, because no test asks for it yet:
- **The password is never checked.** Any password logs in, which is the obvious next RED (wrong password → 401).
- **An unknown email crashes the request** instead of returning a 401.
- **The email isn't lowercased** before the lookup, so a login with different capitalisation won't find the user.
- **`LoginRequest` doesn't validate anything:** fields are plain `str`, not `EmailStr`.

Nothing is committed yet.
