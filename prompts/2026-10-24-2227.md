**What changed:**
- **`app/dependencies.py`:** the placeholder is replaced. The new version reads the token with `HTTPBearer`, gets a user id from `TokenService`, and loads that user with `UserRepository`. It raises `InvalidToken` if the user no longer exists.
- **`app/services/token.py`:** new `TokenService.user_id(token)`. It decodes the token with the configured secret and algorithm and turns any PyJWT `InvalidTokenError` into `InvalidToken`. That error class covers a malformed token, a wrong signature and an expired token.
- **`app/domain/errors.py`:** new `InvalidToken` error with the detail `"Invalid or expired token"`.
- **`app/exception_handlers.py`:** `InvalidToken` returns 401.
- **`app/repositories/user.py`:** new `get_by_id`.

**How each case is rejected:**
- **Missing header:** `HTTPBearer` itself returns 401 with `"Not authenticated"`. FastAPI 0.162 does this by default; older versions returned 403.
- **Garbage, wrong-secret and expired tokens:** each one fails to decode, so `InvalidToken` gives a 401.
- **Deleted user:** the lookup finds no user, so it also gets `InvalidToken` and a 401.

**Gaps, each needing its own test first:**
- **No `WWW-Authenticate` header:** our `InvalidToken` 401s don't send it. `HTTPBearer`'s own 401 for a missing header does.
- **Bad `sub` claim:** a token signed with our secret but with a missing or non-numeric `sub` would cause a 500. Only someone holding our secret could create one, so it's an edge case.

Nothing is committed. Suggested message: `(GREEN) feat: add bearer token authentication dependency`.
