**Test factory**
- `tests/factories.py` has a new `make_vehicle()` fixture, set up the same way as `make_user`. It saves a vehicle straight to the test database with the same defaults as `VEHICLE` (Toyota Corolla, sedan, 24999.99, quantity 5), and you can override any field. It's registered in `conftest.py`.
- In `tests/test_vehicles.py`, every test that only needed vehicles as setup now uses `make_vehicle()`. That covers the listing, update and delete tests. Before, they created vehicles by calling `POST /api/vehicles`.
- Several tests had an admin user only to make that `POST` call, so I removed those admins. The no-token update test no longer creates any users.
- A small `_as_json(vehicle)` helper builds the expected JSON for a vehicle. Every assertion still checks the same status codes and response bodies.
- The create tests (201, 401, 403, 422) still use `POST`, since `POST` is what they test.

**Routes and service**
- The routes were already thin: each one validates input, calls the service and builds the response, with no session access or business rules. The only change in `app/routes/vehicles.py` is a `VehicleServiceDep` shorthand for the service dependency, which shortens every route's parameter list.
- In `app/services/vehicle.py`, `update` and `delete` both repeated "look up the vehicle, raise `VehicleNotFound` if it's missing". That now lives in one private `_get()` helper.
